# S3 And S3-Compatible Backends

This covers AWS S3, Cloudflare R2, Tigris, MinIO, Backblaze B2, Wasabi, DigitalOcean Spaces, Ceph, and NetApp.

## URL Forms

```text
s3://<bucket>
s3://<bucket>/<name>.trunk
r2://<bucket>
tigris://<bucket>
minio://<host>:<port>/<bucket>
```

A backend URL like `s3://company-code` is a storage root. A trunk lives under it:

```text
s3://company-code/trunks/lazy-lms.trunk/
```

An exact `.trunk` URL stays exact:

```text
s3://company-code/custom.trunk/
```

## Credentials

Set env vars before running `trunks`.

| Scheme | Vars |
|---|---|
| `s3://` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, optional `AWS_SESSION_TOKEN`, `AWS_REGION` |
| `r2://` | `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ACCOUNT_ID` |
| `tigris://` | `TIGRIS_ACCESS_KEY_ID`, `TIGRIS_SECRET_ACCESS_KEY` |
| `minio://` | `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` |
| `b2://` | `B2_KEY_ID`, `B2_APPLICATION_KEY` |
| `wasabi://` | `WASABI_ACCESS_KEY_ID`, `WASABI_SECRET_ACCESS_KEY` |
| `spaces://` | `SPACES_ACCESS_KEY_ID`, `SPACES_SECRET_ACCESS_KEY` |
| `ceph://` | `CEPH_ACCESS_KEY_ID`, `CEPH_SECRET_ACCESS_KEY` |

## Connect And Validate

```bash
export AWS_ACCESS_KEY_ID=...
export AWS_SECRET_ACCESS_KEY=...
export AWS_REGION=us-east-1

trunks storage add --name primary --backend s3 --bucket company-code
trunks storage ping primary
```

`storage add` validates by doing real backend I/O before it saves the storage profile. The profile stores bucket, prefix, endpoint, region, role, and any inline credentials you pass. Credentials are local-only in `.trunks/<repo>.trunk`; the remote backend receives only non-secret storage settings.

Provider aliases use the same S3-compatible backend:

```bash
trunks storage add --name primary --backend r2 \
  --bucket company-code \
  --account-id "$R2_ACCOUNT_ID"

trunks storage add --name primary --backend minio \
  --host 127.0.0.1:9000 \
  --bucket company-code
```

## Bucket Layout

```text
trunks/lazy-lms.trunk/
  refs/heads/main
  objects/
  chunks/
  segments/
  journals/
  locks/
```

## Permissions

The credentials need:

- `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on the chosen prefix
- `s3:ListBucket` on the bucket, scoped to the prefix if desired

The bucket should already exist.
